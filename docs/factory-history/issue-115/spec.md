# Move production and cash summary into their domain packages

> Issue #115: Move production and cash summary into their domains

## Summary
- Phase 1 of docs/MIGRATION_PLAN.md: move the production code into `app/production/` (`routes.py`, `service.py`, `repository.py`) and the cash summary code into `app/cash_summary/` (`routes.py`, `service.py`). Pure refactor: no URL, endpoint, template, SQL or log line changes.
- Follows the pattern #113 and #114 set (`app/auth/`, `app/customers/`, `app/pricing/`, `app/inventory/`): `git mv`, a docstring-only package `__init__.py`, callers reach the repository through the module, strict mypy on service and repository, docs point at the new paths.
- `app/core/db/__init__.py` stops re-exporting the 14 production names; every caller (two other blueprints, the service, five test files, two monkeypatches) switches to `production_repository.<name>`.
- The production detail keeps serving declaration files through `app/web/blueprints/declarations.py` and `app/core/db` (declarations move later). Cash summary keeps its SQL, with a `TODO(phase 4)` comment where it reads the orders tables.

## Context
**Files that move:**
- `app/web/blueprints/production.py` (blueprint `"production"`, routes `/produccion`, `/produccion/<id>`, `/produccion/<id>/advance|undo`, and the two declaration-file routes `/produccion/<id>/declarations/<id>/file/<kind>` and `.../cards/<card_id>/photo/<side>`). It defines `PRODUCTION_STATUS_LABELS` and `STATUS_FILTERS`, imports `STATUS_*` from `app.core.db.production`, `advance_order`/`revert_order` from `app.core.production`, `REASON_LOSS` from `app.core.db.declarations`, `CARD_PHOTO_SIDES`/`FILE_KINDS` from `app.web.blueprints.declarations`, and calls `db.get_production_status`, `db.list_production_events`, `db.list_production_orders`, `db.count_by_production_status` plus declaration/order functions that stay in `app.core.db` (`db.list_declaration_cards`, `db.list_declarations_by_production_order`, `db.get_declaration`, `db.DeclarationRecord`, ...).
- `app/core/production.py` (`next_status`, `previous_status`, `advance_order`, `revert_order`, `MSG_*`): imports `from app.core import db` (calls `db.set_production_status`, `db.get_production_status`) and `from app.core.db.production import PRODUCTION_STATUSES, STATUS_DELIVERED, STATUS_PENDING`.
- `app/core/db/production.py` (constants `STATUS_*`, `PRODUCTION_STATUSES`, `ACTIVE_STATUSES`, dataclasses `ProductionOrderSummary`, `ProductionEvent`, functions `list_production_orders`, `count_by_production_status`, `get_production_status`, `set_production_status`, `list_production_events`, `production_statuses_for_orders`). It imports only `app.shared.normalize`, so it is a leaf and creates no import cycle.
- `app/web/blueprints/cash_summary.py` (blueprint `"cash_summary"`, `/cuadre`, `/cuadre/pdf`): imports `build_cash_summary`, `render_cash_summary_pdf` from `app.core.cash_summary`, `db` from `app.core` (for `get_conn`) and `today_iso` from `app.web.helpers`.
- `app/core/cash_summary.py` (`build_cash_summary`, `render_cash_summary_pdf`, dataclasses, `MISSING_PAYMENT_METHOD_LABEL`): two raw SQL queries in `build_cash_summary` read `plates` joined to `production_orders` (around lines 110-140); those are orders-domain tables. It imports no app module.

**Re-exports to remove:** `app/core/db/__init__.py` imports 14 names from `app.core.db.production` (`ACTIVE_STATUSES, PRODUCTION_STATUSES, STATUS_DELIVERED, STATUS_IN_PROGRESS, STATUS_PENDING, STATUS_READY, ProductionEvent, ProductionOrderSummary, count_by_production_status, get_production_status, list_production_events, list_production_orders, production_statuses_for_orders, set_production_status`), lists them in `__all__` and describes `production.py` in its docstring.

**Callers** (from `rg "\bdb\.(<the 14 names>)\b"` and the import search):

- Strings that stay unchanged: `app/web/navigation.py` endpoint names (`production.production`, `cash_summary.cuadre`, ...) and permission codes; the comment in `app/migrations/0016_production_status.sql` (applied migration).

**The pattern to reuse** is #114's (see `docs/factory-history/issue-114/spec.md` and `app/inventory/`): `app/inventory/__init__.py` is a docstring with the domain's dependency rule and no imports; `app/inventory/routes.py` writes `from app.inventory import repository` and `from app.shared import db` and calls `repository.<fn>` and `db.get_conn()`; outside the domain callers alias it (`from app.customers import repository as customers_repository`). `pyproject.toml` lines 52-65 hold the strict `[[tool.mypy.overrides]]` list. `app/core.*` is in that list today, so the three moved non-route modules are strict now and must stay strict. `app/shared/__init__.py` already names `app.production` and `app.cash_summary` as domain packages.

**Docs that name the moved paths:** `docs/CORE.md` (the `db/__init__.py` row, the sections `### db/production.py` at line 588, `### production.py` at 613, `### cash_summary.py` at 655), `docs/WEB.md` (rows for `/produccion*` and `/cuadre*`, plus rows of other routes that cite `db.get_production_status` / `db.production_statuses_for_orders`), `docs/ARCHITECTURE.md` (the domain packages paragraph and diagram added by #113/#114), `docs/PRODUCTION.md` lines 5-7, `docs/DATABASE.md` lines 244, 470, 715, `docs/SIIGO_INTEGRATION.md` line 499, the docstrings of the moved modules, `app/web/app.py`, `app/core/db/__init__.py`, and the test docstrings of `tests/core/test_production.py`, `tests/core/db/test_production.py`, `tests/core/test_cash_summary.py`, `tests/web/test_cash_summary.py`. `docs/MIGRATION_PLAN.md` describes the plan and is left alone, like in #113 and #114.

## Requirements
1. Create `app/production/__init__.py` and `app/cash_summary/__init__.py` holding only a module docstring (no imports). Each says what the domain holds and states its dependency rule: other code may import the domain; the domain imports `app.shared` and `app.auth`; until they move, `app.production` also imports `app.core.db` (orders and declarations data) and `app.web.blueprints.declarations` (the declaration-file constants), and both `routes.py` import `app.web.helpers` where they do today (until phase 6).
2. Move each file with `git mv` (a commit with only the moves is recommended so git records renames), then change only imports, call prefixes, docstrings and comments:
   - `app/web/blueprints/production.py` → `app/production/routes.py`
   - `app/core/production.py` → `app/production/service.py`
   - `app/core/db/production.py` → `app/production/repository.py`
   - `app/web/blueprints/cash_summary.py` → `app/cash_summary/routes.py`
   - `app/core/cash_summary.py` → `app/cash_summary/service.py`
3. Remove the `app.core.db.production` import, its 14 names in `__all__` and its docstring entry from `app/core/db/__init__.py`, and extend the existing "live in ..." docstring line to say the production tables' SQL is in `app/production/repository.py`. Nothing else in that file changes.
4. Callers reach the repository through the module so a monkeypatch on it reaches every call (the #113/#114 rule):
   - Inside the domain (`app/production/routes.py`, `app/production/service.py`): `from app.production import repository` and `repository.<name>` (including the `STATUS_*` / `PRODUCTION_STATUSES` constants, either as `repository.STATUS_PENDING` or imported by name from `app.production.repository`; constants are never monkeypatched).
   - Elsewhere (`app/web/blueprints/declarations.py`, `app/web/blueprints/records.py`, tests): `from app.production import repository as production_repository` and `production_repository.<name>`.
   - The service is imported in routes as `from app.production import service` with `service.advance_order` / `service.revert_order`, or by name as today; either is fine.
   - Calls to names that stay in `app.core.db` (declarations, orders, plates) keep the `db.` prefix, through `from app.core import db`.
5. The production detail page keeps serving declaration files from its two existing routes, still importing `CARD_PHOTO_SIDES`, `FILE_KINDS` from `app.web.blueprints.declarations` and `REASON_LOSS` from `app.core.db.declarations`. No declarations code moves or changes beyond the call prefix of the two production functions it calls.

The SQL text itself is byte-for-byte unchanged. Update the docstring sentence that says "app/core/ never imports from app/web/" so it names the new layer rule (the service does not import `app.web`).

## Out of scope
- Any behaviour change: no new route, permission, label, query, status rule, or template edit.
- Moving or refactoring the orders or declarations code (`app/core/db/orders.py`, `app/core/db/plates.py`, `app/core/db/declarations.py`, `app/core/declarations.py`, `app/web/blueprints/declarations.py`, `records.py`, ...) beyond the call prefix of the production functions they use.
- Moving cash summary's SQL into a repository or the orders domain (that is phase 4; only the `TODO(phase 4)` comment is added).
- Moving `PRODUCTION_STATUS_LABELS` or `STATUS_FILTERS` out of the routes module, or templates out of `app/web/templates/` (phase 6).
- Moving or renaming test files.
- The delivery-signature feature and the phase 4 API described in `docs/MIGRATION_PLAN.md`.
- Editing `factory/checks.sh` or `factory/config.json` (protected).

## Assumptions
- `app/core/db/__init__.py` drops the production re-exports instead of keeping them as a compatibility shim: that is what #113 and #114 did, and acceptance criterion 1 of the issue implies callers stop going through `app.core.db` for this domain.
- Callers outside the domain use the alias `production_repository`: it matches `customers_repository` / `pricing_repository` already used in the same blueprints.
- Only the three non-route modules join the strict mypy list: the issue asks for the bar on modules that came from `app/core/`, and no blueprint is strict today.
- The `TODO(phase 4)` comment treats both `plates` and `production_orders` as orders-domain tables: docs/MIGRATION_PLAN.md puts `core/db/orders.py` and `core/db/plates.py` in the orders domain.
- Tests stay in `tests/core/` and `tests/web/`: #114 kept test files in place and the issue allows only import and monkeypatch changes.
