# Code Mode (REPL, Poll) for every factory agent except intake

> Issue #103: Give factory agents Code Mode (REPL, Poll), except intake

## Summary
- Eight agents in `.claude/agents/` change their `tools:` line to `REPL, Poll`: builder, spec-writer, approver, planner and the four reviewers. The planner keeps its Figma MCP tools. `intake.md` stays byte-for-byte the same, so it still has no shell.
- The prompt lines that name Read/Grep/Glob/Bash/Edit/Write as tools are reworded for Code Mode. The rules don't change: commands start with `cd <worktree> &&`, paths are absolute, and each agent writes one file.
- `factory/bin/sync-agents` gets a mapping: `REPL` becomes the Antigravity native tools these agents had before, and `Poll` becomes nothing. Its note is updated, `.agents/agents/` is regenerated, and a new test covers the mapping.
- The builder can't spawn an agent, so the "does an agent really get REPL" probe and the "does the builder's Stop hook still fire" check are left to the orchestrator or the owner on this branch. The PR says this.

## Context
- **Agent definitions.** These are in `.claude/agents/*.md`. Each file has YAML-like frontmatter (`name`, `description`, `tools`, `model`, and for the builder a `hooks.Stop` entry that runs `"$CLAUDE_PROJECT_DIR"/factory/bin/gate --hook`), followed by a prompt body. The `tools:` lines today:
  - `builder`: `Read, Grep, Glob, Bash, Edit, Write`
  - `spec-writer`, `approver`, `reviewer-code`, `reviewer-security`, `reviewer-ui`, `reviewer-ux`: `Read, Grep, Glob, Bash, Write`
  - `planner`: `Read, Grep, Glob, Bash, Write`, then five `mcp__plugin_figma_figma__*` tools
  - `intake`: `Read, Grep, Glob, Write`. This line must not change.
- **Prompt text that names tools directly** (found by grep; intake excluded):
  - `builder.md` lines 22-23: "start every Bash command with `cd <worktree> && `, and give Read, Edit, Write, Grep and Glob absolute paths under the worktree."
  - `spec-writer.md` lines 16-17, `approver.md` lines 24-25, `reviewer-code.md`, `reviewer-security.md`, `reviewer-ui.md`, `reviewer-ux.md` lines 17-18: the same sentence with "Read, Grep and Glob".
  - `reviewer-*.md` (lines 82-85): "Write the file with your Write tool before you reply: you have it, and the review only counts once the file exists."
  - Headings such as `## Read`, `## Write spec.md` and "Read `AGENTS.md`" use the plain verb, not a tool name. They stay as they are.
- **Antigravity copies.** `.agents/agents/*.md` are generated by `factory/bin/sync-agents`. Its `TOOLS` dict maps Claude Code tool names to Antigravity native names. `render()` calls `die()` on any name it doesn't know, so `REPL` and `Poll` currently break both the generation and `sync-agents --check`, which `factory/checks.sh` runs. The module docstring and the `NOTE` string (a header put into every generated file) explain the tool-name mapping. `mcp__*` tools are already skipped. Antigravity replaces its default tool list with the emitted one, and an unknown name can hang the agent, which is why only known names are emitted.
- **Docs.** The `AGENTS.md` "Antigravity" bullet in `## Software factory` describes the generated agents. `.agents/skills/factory/SKILL.md` "In Antigravity" also describes them. That file is orchestrator text and does not need to change.
- **Test pattern.** `tests/test_factory_test_dbs.py` loads the extension-less `factory/bin/job` script with `importlib.machinery.SourceFileLoader`. Use the same pattern to test `sync-agents`.
- **Gate hook.** `factory/bin/gate --hook` is not changed by this job. The builder's hook only keeps working if its frontmatter block stays intact.

## Requirements
1. In `.claude/agents/`, the `tools:` line of `builder.md`, `spec-writer.md`, `approver.md`, `reviewer-code.md`, `reviewer-security.md`, `reviewer-ui.md` and `reviewer-ux.md` is exactly `tools: REPL, Poll`.
2. The `tools:` line of `planner.md` is `tools: REPL, Poll,` followed by the same five `mcp__plugin_figma_figma__*` entries, in their current order.
3. Nothing else in any agent's frontmatter changes. In particular, `builder.md` keeps its whole `hooks:` / `Stop:` block running `"$CLAUDE_PROJECT_DIR"/factory/bin/gate --hook`.
4. `.claude/agents/intake.md` is byte-for-byte unchanged.
5. In the eight changed agents, prompt text that tells the agent to use Read/Grep/Glob/Edit/Write/Bash as tools is reworded for Code Mode, and the rule it states stays the same:
   - Shell commands run through the REPL's `$`, and each one still starts with `cd <worktree> && `.
   - File reads, searches and writes are done from inside the REPL, still with absolute paths under the worktree. The job folder (or plan folder) file is still the only file written outside it.
   - The reviewers' line becomes "Write the file from the REPL before you reply: …", keeping the point that the review only counts once the file exists.
   - Only the tool references change. Other wording, rules and sections stay as they are.
6. `factory/bin/sync-agents` accepts `REPL` and `Poll`:
   - `REPL` maps to `view_file`, `write_to_file`, `replace_file_content`, `multi_replace_file_content`, `grep_search`, `find_by_name`, `list_dir`, `run_command`.
   - `Poll` maps to no tool at all: nothing is emitted for it.
   - Any other unknown name still makes `render()` die with the existing message.
7. The `sync-agents` docstring and `NOTE` explain the new mapping in one or two sentences. The note must still list the Read/Write/Edit/Grep/Glob/Bash names, because intake's copy uses them. It must also say that where a prompt says REPL (and `$`), the Antigravity agent uses its native file tools and `run_command`, and that `Poll` has no Antigravity equivalent and can be ignored.
8. `.agents/agents/` is regenerated with `factory/bin/sync-agents`, and `factory/bin/sync-agents --check` passes.
9. A new test file, `tests/test_sync_agents.py`, loads `factory/bin/sync-agents` the same way `tests/test_factory_test_dbs.py` loads `job`. It runs `render()` on temporary agent files (under `tmp_path`) and checks:
   - `tools: REPL, Poll` produces the eight native tools above and no `Poll` entry.
   - An `mcp__` tool next to them is still dropped.
   - An unknown tool name still exits with an error (`SystemExit`).

   The test must not write into `.agents/` or `.claude/`.
10. In `AGENTS.md`, the `## Software factory` "Antigravity" bullet gains one short sentence. It says the Claude Code agents except intake run in Code Mode (`tools: REPL, Poll`), and that `sync-agents` gives their Antigravity copies the native file tools and `run_command` in its place.
11. The PR description:
    - says how Antigravity handles `REPL` and `Poll` (REPL becomes the native tools listed above; Poll is dropped);
    - notes the side effect that in Antigravity, approver, reviewers, spec-writer and planner now also get the edit tools, which they didn't have before (they already had `run_command`, so this gives them nothing new in practice);
    - has a "Verification by the orchestrator/owner" section with two unchecked items: (a) a changed agent spawned from this branch reports having `REPL` and `Poll`; (b) the builder's `Stop` hook (`factory/bin/gate --hook`) still fires. It also says that if (a) fails, the change must not merge, and that this should be reported rather than worked around.

## Out of scope
- Any change to `.claude/agents/intake.md` or its rules.
- Permission settings (`.claude/settings*.json`), `CLAUDE.md`, and how the orchestrator spawns agents, including the spawn prompts in `.agents/skills/factory/SKILL.md` and `.claude/skills/factory/SKILL.md`.
- `factory/bin/gate` and the hook command itself, `factory/checks.sh` and `factory/config.json` (the last two are protected paths).
- Hand-editing `.agents/agents/`. Edit only through `sync-agents`.
- Per-agent Antigravity tool lists or new frontmatter keys added to keep the Antigravity side-effect away. The flat REPL mapping is the chosen design.
- Workarounds if listing `REPL, Poll` doesn't give an agent the REPL, such as adding `Bash` back next to it. That outcome gets reported, not patched.
- Any change to the plates app (`app/`, templates, migrations).

## Assumptions
- **`REPL` maps to the full native set, edit tools included.** Reason: these agents already have `run_command`, which can edit files, so the edit tools give them no new power. A per-agent mapping would need new frontmatter, which is more machinery than this job needs.
- **Nothing is emitted for `Poll`.** Reason: Antigravity has no equivalent, and an unknown name can hang the agent.
- **The "start every command with `cd <worktree> && `" rule stays for `$`.** Reason: it isn't known whether the REPL's shell keeps its working directory between calls. Keeping the rule is the safe reading of "the rules themselves don't change."
- **The spawn probe (a) and hook check (b) are done after the build, not by the builder.** Reason: the builder can't spawn agents, and the orchestrator loads agent definitions from the main checkout, so the probe has to run in a session started on this branch. Intake says so explicitly.
- **There is a new pytest file for `sync-agents`.** Reason: the repo already tests factory scripts with `SourceFileLoader`, and the mapping is easy to get wrong without anything catching it.
- **One sentence is added to `AGENTS.md` and nothing to `SKILL.md`.** Reason: AGENTS.md is the maintainer doc for the generated agents. SKILL.md is orchestrator text, which is out of scope.
