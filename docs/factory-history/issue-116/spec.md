# Move the point of sale, records and duplicates review into app/orders/

> Issue #116: Move the point of sale, records and duplicates review into the orders domain

## Summary
- Phase 1 of docs/MIGRATION_PLAN.md: `git mv` the ingest, records and review blueprints, the ingestion pipeline, the pedido parsers and the orders/plates SQL into a new `app/orders/` package. No behavior change: same URLs, endpoints, templates, SQL and log lines.
- Follows the layout #113-#115 set: a docstring-only package `__init__.py`, a `repository/` package that re-exports its names (like `app/customers/repository/`), a `service.py` (like `app/production/service.py`), callers write `orders_repository.<name>`, and strict mypy on everything that came from `app/core/`.
- `app/core/db/__init__.py` stops re-exporting the orders and plates names; every `db.<order/plate function>` caller in app and tests switches to `orders_repository.<name>`.
- The `customers` -> `plates` import (`update_customer` relinks plates) would become a `customers` -> `orders` cycle; it is solved by moving `relink_plates` and its helper next to `resolve_card_id_for_plate` in `app/customers/repository/ownership_cards.py`, so the dependency only points `orders` -> `customers`.

## Assumptions
- `relink_plates` and its helper go to `app/customers/repository/ownership_cards.py` instead of `app/shared/`. Reason: the helper needs `resolve_card_id_for_plate` (customers), and `app/shared/` may not import a domain. Card linking is already the customers domain's rule. Keeping `update_customer`'s behavior means the call cannot move out to its callers.
- The private helper becomes public (`card_id_for_order_plate`) because `plates.py` now imports it across modules. The name is a code identifier, so it is English. Nothing else about it changes.
- The repository is a `repository/` package with `orders.py` and `plates.py`, not one merged file. Reason: `git mv` keeps each file's history, and it matches `app/customers/repository/`.
- Ingestion becomes `app/orders/service.py`, not `app/orders/ingestion.py` plus a re-export. Reason: it matches `app/production/service.py`, and a single module avoids a shim.
- The routes go in an `app/orders/routes/` package, as the issue lists, not one `routes.py`. Reason: three blueprints of 700, 311 and 58 lines stay separate files.
- Tests stay in `tests/core/` and `tests/web/`. Reason: #114 and #115 kept them in place, and the issue allows only import and monkeypatch changes.
- The issue's acceptance-criterion `rg` excludes `docs/factory-history/`. Reason: earlier records quote the old paths, and only the factory writes there.
