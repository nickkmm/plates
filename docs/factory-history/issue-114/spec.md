# Move customers, pricing and inventory into their domain packages

> Issue #114: Move customers, pricing and inventory into their domains

## Summary
- Phase 1 of docs/MIGRATION_PLAN.md: move three small domains into `app/customers/`, `app/pricing/` and `app/inventory/`, each with `routes.py` (the old blueprint) and a repository (the old `app/core/db/` modules). Pure refactor.
- Follows the pattern #113 set for `app/auth/`: `git mv`, a docstring-only package `__init__.py`, callers use `<alias>.<fn>` through the module, strict mypy on the repositories, docs point at the new paths.
- The customers repository is a package (`customers.py` + `ownership_cards.py`) so both files keep their history.
- The one real hazard is an import cycle (customers SQL calls `app.core.db.plates.relink_plates`, and `plates.py` calls ownership-card and pricing SQL). The spec fixes how imports are written so no import order breaks.
- No URL, endpoint, template, SQL, log line or test is changed beyond imports, call prefixes and docstrings.

## Context
**Files that move** (all short: 39 to 249 lines):
- `app/web/blueprints/customers.py` (blueprint `"customers"`, routes `/customers`, `/customers/<id>` GET/POST). It calls `db.get_conn`, `db.list_customers`, `db.get_customer`, `db.list_ownership_cards_for_customer`, `db.update_customer` and imports `customer_fields_from_form` from `app/web/helpers.py`. Its only non-HTML logic is a one-line name filter, which is too small to justify a service.
- `app/web/blueprints/pricing.py` (blueprint `"pricing"`, `/precios`): `db.price_list`, `db.set_price`.
- `app/web/blueprints/inventory.py` (blueprint `"inventory"`, `/inventory`): `db.inventory_view`, `ornamental_count`, `insert_blank_preparation`, `recalc_inventory`; imports `INVENTORY_CATS` from `app/web/helpers.py`.
- `app/core/db/customers.py` (imports `from app.core.db.plates import relink_plates`), `app/core/db/ownership_cards.py` (imports only `app.shared`), `app/core/db/pricing.py` and `app/core/db/inventory.py` (both import only `app.shared`).

**Re-exports to remove**: `app/core/db/__init__.py` re-exports 30 names from these four modules: customers (`CustomerRecord, get_customer, get_customer_by_name, list_customers, resolve_or_create_customer, update_customer`), inventory (`insert_blank_preparation, inventory_view, ornamental_count, recalc_inventory`), ownership_cards (`CARD_LINK_EXCLUDED_CUSTOMER_TYPES, CARD_STATUS_DATA_MISMATCH, CARD_STATUS_NEW, CARD_STATUS_OTHER_OWNER, CARD_STATUS_SAME_CARD, CardLookup, OwnershipCardRecord, classify_card_lookup, create_ownership_card, find_card_conflicts, get_ownership_card, get_ownership_card_by_plate_number, get_ownership_card_by_transit_license, list_ownership_cards_for_customer, reassign_ownership_card, resolve_card_id_for_plate`) and pricing (`PriceRow, current_prices, price_list, set_price`). Its docstring lists the four modules.

**Callers** (from `rg -c` of `db.<moved name>`, about 380 sites):
- app: `app/core/db/plates.py` (direct imports of `resolve_card_id_for_plate` and `current_prices`), `app/core/db/orders.py` (docstring only), `app/core/declarations.py` (23 sites, including type annotations such as `db.CustomerRecord`, `db.CardLookup`), `app/core/ingestion.py` (9), `app/migrate.py` (1), `app/web/helpers.py` (docstring), and the `declarations`, `ingest`, `records`, `review` blueprints in `app/web/blueprints/`, plus `app/web/app.py` lines 69, 72-73 and 113-117 (imports and registration).
- tests: `tests/conftest.py`, `tests/core/db/test_{customers,ownership_cards,pricing,inventory,plates,orders,declarations}.py`, `tests/core/test_{declarations,ingestion}.py`, `tests/web/test_{customers,pricing,inventory,csrf,declarations,ingest,records,review,public_declaration}.py`. No test monkeypatches a moved name. `tests/conftest.py` patches `get_conn` on both `app.core.db` and `app.shared.db` (around line 437), so routes may take `get_conn` from either.
- Comments only, which must stay unchanged: `app/web/templates/ingest.html:465` (templates are frozen), `app/migrations/0002_reference_integrity.sql`, `0006_ownership_cards.sql`, `0008_plates_ownership_card_id.sql` (applied migrations).

**The pattern to reuse** is #113's `app/auth/` (see `docs/factory-history/issue-113/spec.md`): `app/auth/__init__.py` is a docstring only; `app/auth/repository/__init__.py` explicitly re-exports its submodules' names with `__all__`; callers write `from app.auth import repository` and call `repository.<fn>`; `app/auth/admin_routes.py` takes `get_conn` from `from app.shared import db`; `pyproject.toml` lists the strict modules in the `[[tool.mypy.overrides]]` with `disallow_untyped_defs = true` (lines 52-61).

**Import cycle.** After the move, `app/core/db/plates.py` needs ownership-card and pricing SQL, and the customers repository needs `app.core.db.plates.relink_plates`. A name import (`from app.core.db.plates import relink_plates` inside the customers repository, or `from app.customers.repository import resolve_card_id_for_plate` inside `plates.py`) fails with `ImportError` depending on which module is imported first. Importing the module object instead (`from app.core.db import plates`, then `plates.relink_plates(...)` at call time) and importing the leaf submodule by full path in `plates.py` (`from app.customers.repository.ownership_cards import resolve_card_id_for_plate`) works in every order, because neither leaf (`ownership_cards.py`, the pricing repository) imports anything but `app.shared`.

**Docs that name the moved paths**: `docs/CORE.md` (the `db/` table rows at lines 303-307 and the sections `### db/customers.py`, `### db/ownership_cards.py`, `### db/pricing.py`, the `db/__init__.py` row at 302), `docs/WEB.md` (route rows at lines 33-39 naming `inventory.py`/`pricing.py`/`customers.py` and `db.<fn>`; other rows that cite `db.current_prices`, `db.list_customers`, `db.get_customer`, `db.resolve_or_create_customer`), `docs/ARCHITECTURE.md` (the layer diagram and the `app/auth/` paragraph after it), `docs/DATABASE.md` (lines 206, 263, 319, 732, 777), `docs/README.md` (CORE/WEB rows), `README.md` (lines 82-86), `docs/LOCAL_DEVELOPMENT.md` line 88, `app/shared/models.py` line 73, and the test docstrings of `tests/core/db/test_{customers,ownership_cards,pricing,inventory}.py` and `tests/web/test_inventory.py`. `docs/MIGRATION_PLAN.md` describes the plan and is left alone, like in #113.

## Requirements
1. Create the packages with `__init__.py` files that hold only a module docstring and no imports: `app/customers/__init__.py`, `app/pricing/__init__.py`, `app/inventory/__init__.py`. Each docstring says what the domain holds and states the dependency rule: other code may import the domain; the domain imports `app.shared`, `app.auth` and, until those are moved, `app.core.db.plates` (customers) and `app.web.helpers` (routes, until phase 6).
2. Move each file with `git mv` (one commit with only the moves is recommended so git sees renames), then change only imports, call prefixes, docstrings and comments:
   - `app/web/blueprints/customers.py` → `app/customers/routes.py`
   - `app/core/db/customers.py` → `app/customers/repository/customers.py`
   - `app/core/db/ownership_cards.py` → `app/customers/repository/ownership_cards.py`
   - `app/web/blueprints/pricing.py` → `app/pricing/routes.py`
   - `app/core/db/pricing.py` → `app/pricing/repository.py`
   - `app/web/blueprints/inventory.py` → `app/inventory/routes.py`
   - `app/core/db/inventory.py` → `app/inventory/repository.py`
3. Create `app/customers/repository/__init__.py`: an explicit re-export (no `import *`) of every name `app/core/db/__init__.py` exported from `customers` and `ownership_cards`, with a matching `__all__`, and a docstring listing the two submodules and pointing to `app/shared/db.py` for the connection and transaction contract.
4. Break the import cycle as described in Context:
   - `app/customers/repository/customers.py` imports the module (`from app.core.db import plates`) and calls `plates.relink_plates(...)`.
   - `app/core/db/plates.py` imports `resolve_card_id_for_plate` from `app.customers.repository.ownership_cards` and `current_prices` from `app.pricing.repository`.
   - Any equivalent that passes Acceptance criterion 4 is fine, but no function-local import is added just to dodge the cycle.
5. Callers reach the moved code through the module, not by importing names, so a monkeypatch on the repository module reaches the call (the #113 rule). Inside a domain's own `routes.py` write `from app.customers import repository` (or `app.pricing`, `app.inventory`) and call `repository.<fn>`. Elsewhere use the aliases `customers_repository`, `pricing_repository`, `inventory_repository` (for example `from app.customers import repository as customers_repository`). The exceptions are the two leaf imports in Requirement 4 and type-only names (`CustomerRecord`, `CardLookup`, `PriceRow`, ...), which may be imported by name or used as `customers_repository.CustomerRecord`.
6. Remove the customers, ownership_cards, pricing and inventory imports, their 30 names in `__all__` and their docstring entries from `app/core/db/__init__.py`. The docstring gets one line saying where these tables now live (`app/customers/repository/`, `app/pricing/repository.py`, `app/inventory/repository.py`), like the existing users/roles line. Nothing else in that file changes.
7. Update every caller listed in Context: `app/web/app.py` imports the three blueprints from `app.customers.routes`, `app.pricing.routes`, `app.inventory.routes` (registration order and blueprint variable names unchanged); `app/core/declarations.py`, `app/core/ingestion.py`, `app/migrate.py` and the `declarations`, `ingest`, `records`, `review` blueprints use the aliased repositories; the three new `routes.py` take `get_conn` from `app.shared.db` (as `app/auth/admin_routes.py` does). Calls to names that stay in `app.core.db` keep the `db.` prefix.
8. Update the tests: imports, the `db.` prefix of moved names, and docstrings only. Test files stay where they are. No test is deleted, skipped, renamed or weakened, and the collected test count equals `origin/main`'s.
9. Blueprint names (`"customers"`, `"pricing"`, `"inventory"`), endpoints, URLs, templates (still in `app/web/templates/`, found by the Flask app's template folder as today), flash and log messages, SQL and behaviour are unchanged. `app/web/helpers.py` stays in `app/web/` (only its docstring changes).

## Assumptions
- **Customers repository is a package** (`repository/customers.py` + `ownership_cards.py`): both `git mv`s keep history and it matches `app/auth/repository/`; the issue allows either layout.
- **No `app/customers/service.py`**: the blueprint's only non-HTML logic is a one-line name filter; the issue makes the service optional and the smallest change wins.
- **Ownership cards belong to customers**: the issue and the "Where today's code goes" table both put `ownership_cards.py` in `customers/`.
- **Aliased module imports** (`customers_repository` etc.) outside each domain: several callers use two or three repositories at once, so a bare `repository` name would clash; module access keeps monkeypatch targets live, as in #113.
- **Temporary dependency on `app.core.db.plates`**: `update_customer` must keep calling `relink_plates`, and plates moves with orders in a later phase-1 task, so `app.customers` imports it for now.
- **Routes keep using `app/web/helpers.py`**: the issue keeps HTML helpers in `app/web/` until phase 6.
- **Frozen files excluded from the `rg` checks**: `docs/factory-history/` (intake), applied migrations (CLAUDE.md forbids editing them), `app/web/templates/` (the issue freezes templates) and `docs/MIGRATION_PLAN.md` (it maps today's paths on purpose).
- **Extra docs updated** (`DATABASE.md`, `README.md`, `docs/README.md`, `LOCAL_DEVELOPMENT.md`) beyond the three the issue names: a path the code no longer has is a stale doc, and #113 did the same.
